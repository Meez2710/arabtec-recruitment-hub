# Request-to-offer workflow audit — findings and fixes (Claude)

Date: 5 October 2026. Implementation: Claude. Inspection, HR recommendations and the release gate: Codex.
Scope: the on-premises legacy runtime (`backend/src/server.js`, `frontend/public`). Baseline checkout `98129346`; live `2beef222`.
Companion records, not edited here: `HR_WORKFLOW_REVIEW.md` (Codex's ownership map and reproductions) and `OFFER_TEMPLATE_REVIEW.md` (Codex's template review).
The verified commit, the test totals and the evidence paths are in `CLAUDE_HANDOFF.md`.

All reproductions ran on synthetic data with `SMTP_TRANSPORT=json`. No mail was sent, no production record was read or written, and no database was deleted.

## Severity key
- **P1**: wrong outcome on record (a commitment, candidate status or approval that does not match what was decided).
- **P2**: misleading or missing information that leads people to the wrong action.
- **P3**: friction or discoverability.

## Policy questions (recorded, not changed)
- **Q-01 On-hold requests.** Should an approved offer be sent, or an interview scheduled, while its request is on hold? Today both are allowed. A hold is a pause, so the answer is an HR policy choice.
- **Q-02 Offer reference numbering.** The letter reference is `YY/HR/DM/MH-ofr/` plus the ATS offer number, which starts at 00001. The paper series had reached 00231 in July 2026, so the first ATS letters will repeat numbers already used on paper this year. Choose whether to continue from the paper series (e.g. a configured starting number). The `HR/DM/MH` part is the same in all three originals and is kept fixed. Confirm whether it stands for people who may change.
- **Q-03 Probation period.** All three originals say "Three months." It is kept fixed. Confirm whether other periods are permitted before making it a choice.
- **Q-04 Final assessment before an offer.** The owner has decided it is decision support, not a gate. No gate was added.
- **Q-05 Candidates linked before request approval** (open item from the 4 Oct review). Unchanged.
- **Q-06 After a sent offer is withdrawn**, the application stays at Offer Sent (there is no transition back to Issuing Offer). A new offer can still be prepared and sent (tested). Decide whether withdrawal should move the application.
- **Q-07 Offers created straight from an early stage** (e.g. Matched) skip the interview stages. This is manual flexibility in the current design and was left as is.

## Residual limitations
- The letterhead uses the vector Arabtec mark plus a text wordmark ("arabtec" in a Gill Sans–style face). The originals are scans of a printed letterhead, and no vector file of that exact lockup is in the repository. Fonts follow the originals (Times New Roman body), but the rendering engine's fallbacks apply.
- The email carries the letter as an HTML attachment the candidate can print. The server has no PDF engine, so no PDF is generated. "Print / save as PDF" in the browser produces a two-page A4 PDF, checked visually against the Bishoy original.
- Actual SMTP or Graph delivery was not exercised (json transport by rule). Delivery outcomes are verified through the mailer's result path.
- The standalone "New candidate" fields require an email or phone, but the form marks neither as required (an existing UX gap).
- HawkScan is not run (`HAWK_API_KEY` not set).
- `dashboard_director_test` moved its default port from 4398 to 4386 so it no longer collides with Codex's preview server on 4398 (test-only change).
